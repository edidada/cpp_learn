# C++98 学习示例（cpp98 分支）

> 本分支对应 git 分支 `cpp98`，是最早的标准分支，汇集 C++98 时代的基础语法与经典实现示例，覆盖**类与友元**、**类模板**、**内存分配（malloc 风格）**、**二叉搜索树集合**等主题，用于理解 C++ 的底层基础与 C 语言的血缘关系。

## 核心示例清单（src/）

| 文件 | 功能说明 | 知识点 |
| --- | --- | --- |
| `AA.h` / `AA.cpp` | 类 AA + 友元函数 | 类封装、`friend` 友元函数访问私有成员、`static` 成员、虚析构 |
| `NoThisFriendClass.h/.cpp` + `_main.cpp` | 友元类示例 | 类间友元关系、非成员友元、跨类访问私有数据 |
| `main.cpp` | AA 使用示例 | 创建对象、调用友元函数 `Disp(a)` |
| `mymalloc.cpp` | 自定义内存分配器 | `sbrk` 扩展堆、空闲块链表 `struct block`、`ALIGN` 内存对齐、首次适应算法（malloc 风格） |
| `myset_b_tree.cpp` | 二叉搜索树集合 | 模板类、`unique_ptr` 管理节点、递归插入/查找、中序遍历 |

> 说明：`mymalloc.cpp` 采用 **C 风格**实现（`struct` + `sbrk` + 宏对齐），直接对应 `malloc`/`free` 的原理；`myset_b_tree.cpp` 虽基于模板，但节点管理已采用现代智能指针（后续合并带入），可作为早期代码与现代写法的对比样本。

## 编译运行

项目使用 CMake 管理，例如：

```bash
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Debug
cmake --build . --target mymalloc
```

## 学习路径建议

1. 类与友元：`AA` → `NoThisFriendClass`（理解 `public/protected/private` 与 `friend` 的访问控制）
2. 底层内存：`mymalloc`（理解堆内存、对齐、空闲块管理的本质）
3. 数据结构：`myset_b_tree`（模板 + 指针实现集合）

## C++98 特性解决了什么问题？

C++98 是首个 ISO 标准化的 C++（1998 年），它在 **C 语言** 之上确立的语言基础能力：

| 特性 | 解决的问题 | C 时代/之前方案与不足 |
| --- | --- | --- |
| **类与封装** | 数据 + 操作绑定、`private/protected/public` 控制访问 | C 用 `struct` + 全局函数，数据全部公开，容易误改；命名靠前缀（如 `obj_xxx()`）易冲突 |
| **构造函数/析构函数** | 对象创建/销毁自动执行（RAII 雏形） | C 必须手动调用 `init()`/`free()`，忘记调用导致资源泄漏 |
| **继承与虚函数** | 代码复用、运行时多态（`virtual` 动态分派） | C 用函数指针表（`struct { void (*fn)(); }`）手写"虚表"，繁琐易错、类型不安全 |
| **运算符重载** | 自定义类型支持自然语法（`a + b`、`a[i]`） | C 只能写 `add(a,b)`、`at(a,i)` 等函数，表达式不直观 |
| **模板** | 泛型代码，一份实现适配多种类型 | C 用 `void*` + 宏 `#define`，`void*` 丢失类型信息、宏无类型检查，排错困难 |
| **RTTI（typeid/dynamic_cast）** | 运行时识别对象真实类型、安全向下转型 | C 无等价物，只能靠手写类型标志位（`enum type`）或约定，极易出错 |
| **异常处理** | 错误沿调用栈传播、对象析构自动清理 | C 用错误码（`errno`）+ `setjmp/longjmp`；错误码易被忽略，`longjmp` 跳过栈上对象的清理，行为危险 |
| **标准库（STL）** | 容器（vector/map/string）+ 算法 + 迭代器统一抽象 | C 标准库只有数组、链表需自写；手工管理内存与大小，越界/泄漏高发 |
| **命名空间 `std`** | 隔离库符号 | C 没有命名空间，只能靠 `_` 前缀约定，大型项目符号冲突严重 |
| **IO 流 `iostream`** | 类型安全的输入输出 | C 的 `printf/scanf` 靠格式串（`%d`）匹配，参数类型不匹配是未定义行为 |

## 与 C / Rust 的对比

| 维度 | C | C++98 | Rust |
| --- | --- | --- | --- |
| **内存安全** | 手动 malloc/free，泄漏/悬垂/UAF 全凭自觉 | 手动 + 局部 RAII（析构），仍易泄漏 | 编译期所有权 + 借用检查，默认安全 |
| **泛型** | `void*`/宏，类型不安全 | 模板，编译期展开，类型安全（报错信息差） | 泛型 + Trait 约束，类型安全且报错清晰 |
| **多态** | 手写函数指针表 | 虚函数（动态分派，vptr/vtable） | `dyn Trait`（trait 对象，动态分派） |
| **错误处理** | `errno`/返回值，易忽略 | 异常（`try/catch`），代价高、易吞 | `Result<T,E>` 枚举 + `?` 传播，显式不可忽略 |
| **资源管理** | 无机制 | 构造/析构 + `auto_ptr`（C++98 弱所有权） | `Drop` trait + 所有权转移，精确且安全 |
| **空指针** | `NULL` 宏（整数 0），无类型 | `NULL` 同 C；无 `nullptr`（C++11 才有） | 无空指针，用 `Option<T>` |
| **并发** | pthread/Win32 手工管理 | 无标准线程库（需 pthread 等第三方） | `std::thread`/`Arc`/`Mutex` 内建于标准库 |

**一句话总结**：C++98 把 C 的结构化编程升级为"面向对象 + 泛型 + RAII"，解决的是 **C 语言在大型项目中代码组织、复用、类型安全、资源管理** 的根本痛点；但受限于时代，它依然没有内建线程库、没有 `nullptr`、所有权模型粗糙（`auto_ptr` 拷贝即转移）——这些短板正是 C++11 以及 Rust 后来重点解决的。
